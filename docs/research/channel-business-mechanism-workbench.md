# 🕸️ 渠道经营机制沙盘：从看板到可推演的业务网络

> [!abstract]
> **不是把一份PPT搬进HTML，不是仅通过点击切换数据，更不是仅为自己日常盯数的运营驾驶舱。** 用户希望构建的是用于**领导汇报与跨部门交流分享**的、视觉高级且可当场操控的**交互式渠道经营机制沙盘（Interactive Business Dynamics Atlas / Regional Channel Atlas）**：在同一持续存在的经营空间中，看见国家、渠道、产品、Margin、ARS、代理商与WOS之间的关系；修改一处业务条件，观察根据明确规则发生的跨模块连锁反应，并能回看计算依据、假设与时间传导。**四层优先级：P0业务/数据联动正确 → P1交互正确 → P2复杂推演 → P3审美品质。**

> [!info] 来源与事实边界
> 本文源自 **2026-11-07晚至2026-11-08凌晨的连续对话**（明确目标、补齐7类业务、制作12页HTML样稿后纠偏、提出“排盘/推演”类比、确定开发优先级）。**Fact**：用户确认的使用场景、业务模块、公式表述、优先级和对PPT式样稿的反馈；**Inference / Design proposal**：本页提出的对象模型、状态机、演示路径与技术实现选项；**Assumption**：Margin对代理商投入/终端动销等行为变量的影响参数。**并没有完成能跨七模块真实运算的HTML沙盘或校准的经营预测模型；既有可交互HTML与12页样稿不能算作该目标已实现。** 本次整理不包含真实公司经营数据或未经授权的文件。

> [!info] 2026-11-08 交互原型已迭代到 V0.2
> 原型从V0.1的**业务关系网络主屏**转成V0.2的**3D国家经营地图（静态阶段快照）+机制推演（动态情景）**双层空间。已在Nebula归档两份完整HTML及视觉索引，见 [综合-东南亚3D经营地图与机制推演双层空间原型](map-simulation-layering.md)。注意：这是原型进展，不等于七模块实数据闭合、真实因果估计或生产级系统已完成。P0–P3质量门槛保持不变。

## 一、需求演化：几次关键纠偏不能被抹平

| 讨论阶段 | 最初理解 / 尝试 | 用户纠偏与最终认识 |
|:---|:---|:---|
| 看板视觉实验 | 经营、渠道结构、流程治理分别做图表/切换主题 | 风格与版式分类有价值，但只是表现层 |
| 七模块经营结构 | 经营/产品/Margin/ARS/代理商/WOS/综合诊断，可做完整汇报 | 模块必须互相影响；不只是分别展示现状 |
| 汇报用途澄清 | “不是日常管理”，于是转成12页、每页一结论的HTML/PDF汇报 | **这仍是PPT思路**；用户要的是展示大屏、复杂的交互、低调酷炫、业务关系演示 |
| 交互定义纠偏 | 点击国家、切换渠道/产品、展开数据详情 | 不只切换视图，而是改变输入后**演示前因后果、跨模块连锁反应** |
| 排盘/推演类比 | 静态“盘面”与模块拼贴 | “盘”是统一空间的系统状态，“推演”是有规则、有边界、有证据的动态演变 |
| 最终排序 | 功能与美感并重 | **P0业务逻辑和数据影响打通 > P1交互逻辑 > P2复杂推演 > P3审美在线**；美学应尽早参与信息架构，但最终验收不可压过真实性 |

**反模式**：
- “做了十几页精美页面，每页一个结论”不满足目标，哪怕HTML可翻页、可全屏。
- “点选国家/切换Tab导致卡片变换”只有数据浏览，没有机制推演。
- “拖动Margin时任意硬编码销量上涨动画”只有情节，没有可解释模型。
- “炫酷粒子、发光连线、3D地图”若不承载真实业务依赖，只是装饰。
- “把七模块一股脑塞一屏”只是密度高，并不意味着系统联动。

## 二、用途与展示体验：大屏 ≠ 日常自用驾驶舱 ≠ PPT

### 使用者与目标
- **领导汇报**：用少量高价值操作迅速展示“一个决策为什么重要、影响什么、代价是什么”；讲述者能主导推演路径。
- **跨部门交流**：不同部门可以从自己关注的节点（销售、渠道、BU、财务、零售等）回溯同一证据与规则，理解业务关系和权责接口；不依赖汇报者逐页讲解。
- **会后复盘**：保存基线与多个推演场景，复现输入、规则版本、输出与关键路径；静态快照/摘要可作为辅助交付，但不是主产品。

### 交互空间
- **Persistent Canvas / 持续画布**：核心对象网络/空间地图不退出，选择国家或代理商时是视角聚焦或下沉为子图，保留上下文和返回路径。
- **Linked Views / 同步投影**：经营结果、产品、库存、Margin、ARS与代理商是同一数据模型的多种视角，不能各自生成不一致的数字。
- **Scenario Dock / 干预台**：调整点位、分货、费用、需求弹性、时滞等，明确显示哪些变量是观测值、决策输入、模型估计或假设。
- **Propagation Trace / 传导追踪**：变化从哪条规则启动、沿哪些节点传递、何时生效、哪些约束被触发。
- **Before/After / Compare**：基线、方案A、方案B对比，可撤销/重置、复制情景并回放过程。

> [!important] 展示不等于实时经营管理
> 可采用合成数据或授权快照的**叙事型、可操控演示模式**，不必先建设日常实时数据平台。但演示模式也应通过公式、守恒和模型依赖校验，不能只做视觉假象。

## 三、七模块：七个观察层，不是七张互不相通的页面

| 模块 | 核心对象/观测量 | 可影响其他模块的关系 | 常用交互切入 |
|:---|:---|:---|:---|
| 1. 国家与渠道经营 | Country、渠道路径、Sell-in/Sell-out、增长/结构、KA | 终端需求关联库存与产品，渠道组合影响利润和覆盖 | 比较国家，展开线下分销/线上分销/KA |
| 2. 产品 | Product/SKU、上市周期、渠道/国家表现 | 新品替代、需求与可售库存影响增长和WOS | 选择产品跨国/跨渠道观察 |
| 3. Margin | RRP、DP、代理/零售点位、返利/促销/实际兑现口径 | 重分配单位经济性，进而可能影响渠道行为和盈利 | 调整总点位或渠道分配 |
| 4. ARS成本结构 | Authorized Retail Store、租金/人力/费用、门店收入 | 门店成本决定所需毛利空间，经营质量影响点位政策 | 查看成本覆盖、盈亏平衡、店型差异 |
| 5. 代理商 | 代理商画像、能力匹配、合同/资源、历次考核 | 执行能力和投入约束影响覆盖、终端动销、回款/库存 | 跨国代理横向对照，展开代理画像 |
| 6. 货盘/WOS | 国家×产品×渠道库存、出货、动销、在途、WOS | 分货节奏与需求变化影响库存健康、资金及渠道策略 | 修改分货、时间或需求假设，追踪WOS |
| 7. 综合分析 | 增长质量、链路经济性、经营矛盾、方案组合 | 将以上各模块变化转成可解释的决策比较与协同问题 | 比较情景，查看变化贡献和待决事项 |

**粒度提醒**：线下分销/线上分销/KA是销售路径或客户类型，ARS是零售终端形态，一个ARS可能属于分销链路的下游。不能把不同维度的规模不加去重地直接相加；国家、产品、渠道路径、合作主体、终端类型、时点必须有清晰ID、关系和统计口径。

## 四、统一模型：从“显示值”升级为“可计算状态”

> **建议概念层架构（非已实现能力）**：
>
> `Object / Relationship / Metric Definition / State / Action / Rule / Simulation Clock / Scenario / GraphView / Evidence`
>
> 每一次改变只提交**动作与参数**，随后统一计算引擎基于共享状态求得新结果；UI从该结果投影，而不是七个组件各自拼凑数字。

- **Object**：Country、Market、Distributor、Retail Chain、ARS、Store、Product、Inventory Bucket、Contract、Policy。
- **Relationship**：供应、授权、资金流、库存归属、零售覆盖、流程责任；连线需标明类型、方向、有效期、计量单位。
- **State**：同一 `scenarioId / period / objectId` 下的完整业务状态；静态基线不可被模拟操作覆盖。
- **Action**：`change-margin`、`reallocate-stock`、`change-cost`、`adjust-channel-investment` 等，需输入合法性校验。
- **Rule**：明确输入、公式、约束、适用条件、证据强度、规则版本和输出影响；区分硬公式与未经验证的行为模型。
- **Simulation**：按时间步/事件推进，处理延迟与反馈；不允许没有收敛/停止规则的循环传播。
- **Scenario**：基线+干预集+假设集+时长+模型版本，可对比、回放、撤销。
- **GraphView**：从同一事实网络按国家、渠道、产品或责任视角进行投影；**不复制一套独立事实**。
- **Evidence**：所有结论或推断都能点击追溯来源/公式/适用范围；无证据则标为假设。

与 概念-Weft因陀罗网递归图与证据语义 的 `Composition / Projection / Dependency` 对应：一个国家或代理商可以展开子盘；同一对象可被不同视角映照；变化传导通过显式依赖规则实现。**这只是设计映射，不代表 Weft 已实现此类推演模块，更不意味着必须先把Weft Core重写。**

## 五、三种规则的认识论分层

| 等级 | 类型 | 示例 | 验收约束 |
|:---|:---|:---|:---|
| R0 | **确定性/合同数学** | 在统一同口径RRP基数下，`DP = RRP × (1 - total_margin)` | 结果精确复算、边界和单位一致、总和守恒 |
| R1 | **条件性动态计算** | 给定库存与周动销，`WOS = 可售库存 / 周动销`；分货改变库存 | 标注假设、期间、时间延迟、库存可售/在途定义、零动销处理 |
| R2 | **行为性/经验假设** | 零售端点位提高可能改变门店投入，进而影响 Sell-out | 不得从点位直接推断销量必增；需要弹性区间、滞后、竞争性解释及情景对比 |

> [!warning] 必须避免“伪因果动画”
> 算术恒等式不等于经验因果；关联关系不等于因果关系；图上连线只能证明模型中存在某种“规则依赖”或“假设路径”，不能凭连线证明现实必然如此。对行为规则必须展示不确定性、敏感度或“未建模”的结果。

### Margin一致性示例（完全合成）
给定 `RRP=100`，分销商点位10pt，零售商20pt，总点位30pt，`DP=70`。零售商+3pt时，至少两种不同干预：
- **总点位锁定30pt**：分销商从10pt→7pt、零售商20pt→23pt，DP仍70；渠道内部重新分配利润空间。
- **分销商维持10pt、总点位扩张**：总点位30pt→33pt，DP从70→67；在相同RRP/单位销量假设下，厂家单位供货收入减少3。
- 上述点位加总仅在用户所述**共同RRP计量基准**下成立；不同环节如果采用顺序乘法、含税价格/补贴/返利口径，则需要独立合同规则，不能直接相加。

### WOS与库存模型要核验
- `WOS = 库存单位数 ÷ 未来/历史基准周动销量` 是一个**必须标明选用分母**的指标；跨国、跨渠道、跨产品的阈值不应无证据统一。
- `期末库存 = 期初库存 + 实际入库 - 实际出库 ± 调整`；调拨/跨渠道移动要有相应扣减与增加，避免重复库存。
- WOS在分母为零、产品刚上市、缺货导致实际动销受限、库存归属不明等情况下，可能不适合被“自动判红绿灯”。

### ARS经济性模型要核验
- 毛利空间与实际P&L不等价：租金、人力、固定费、变动费、促销补贴、税费、库存占用、资本成本口径需统一。
- 可用`所需零售毛利率 = 变动费用率 + (固定费用 + 目标经营利润)/净销售额`做简化情景测算，但不能据此自动认定点位不合理。
- 代理商“画像匹配度/考核”是多维评价，不应在缺少验证时被一个综合分直接转换成动销弹性。

## 六、最小可执行演示：一个干预产生跨模块影响

**唯一建议先完整打通的主线：** 泰国（合成国家案例）→ 选一款产品与其渠道关系 → 零售端Margin上调3pt → 对比两种点位政策 → 追踪分销商/零售商单位经济性 → 引入不同渠道行为假设 → 沿时间轴更新Sell-out与库存 → 查看WOS及ARS成本覆盖 → 比较综合经营输出。

| 步骤 | 可见操作 | 系统需要给出的证据/结果 |
|:---|:---|:---|
| 0 | 冻结基线 | 所有模块口径一致、基线版本可还原 |
| 1 | 选择国家、产品和渠道节点 | 聚焦子图但保留全局关系与返回路线 |
| 2 | 执行 `retailer_margin +3pt` | 区分总点位固定与扩张，两种路径单位经济性分别闭合 |
| 3 | 检查分销商、零售商、ARS | 传导到点位和成本覆盖；行为相关输出保持“未定/情景” |
| 4 | 设置行为弹性、需求和时滞 | 明确参数是假设，生成情景A/B及区间 |
| 5 | 按周推进库存与动销 | 仅在拥有模型时计算WOS趋势，标注约束/反馈 |
| 6 | 切换综合视角与比较 | 展示各情景经营结果、风险和解释链条；能回放/重置 |

**验收不是看到数字变化就通过**：干预必须更新所有应受影响的视图；不相关的数据不可无故改变；对同一状态反复投影结果一致；重放应可复现；未经建模的结果明确为未知。

## 七、开发优先级与并行审美工作线

| 门槛 | 用户最终确认的优先级 | 必须满足的验收 |
|:---|:---|:---|
| **P0** | **业务模型正确、数据影响打通** | 对象/口径/公式/依赖/约束/汇总一致；跨模块数据同源；守恒与边界测试通过 |
| **P1** | **交互逻辑正确** | 聚焦、筛选、下钻、回退、改参、撤销、重置、情景切换均不丢上下文 |
| **P2** | **复杂推演与模拟** | 多变量、时滞、反馈、约束传播、分支情景、回放和可解释影响路径 |
| **P3** | **审美风格在线** | 高端大屏、精密空间关系、低调但有表现力的动效、可读性和层级不牺牲 |

> [!important] P3在验收排序靠后，不等于开发最后一天才想视觉
> **功能主线**：业务模型 → 交互状态 → 推演引擎 → 验证。**设计主线并行**：信息架构 → 空间拓扑 → 视觉语法 → 联动动效 → 视觉验收。布局、空间层级、边合并与动效从早期就影响模型的可理解性，但不能倒过来牺牲计算正确性。

## 八、视觉方向与反炫技原则

- **气质**：克制、酷炫、高端、严谨；参考精密经营分析空间而非传统16:9翻页PPT。
- **结构**：一张持续画布是主舞台，国家/代理/产品可变成可展开子盘，辅助模块围绕选中关系适度显隐。
- **色彩与材质**：暗色建筑感、低饱和青绿和暖金作为状态/影响区分；避免装饰性彩虹、持续粒子飞舞。
- **动态**：变化沿真实依赖边传播，节点响应按因果类型/方向/时间组织；支持暂停、逐步推进和回放。
- **版式分类**：Executive Brief、Bento、Command、Network、Master-detail等仍是**可用设计语法**，不是最终产品必须分页的结构。最适合的组合可能是`Persistent Network Canvas + Context Dock + Scenario Dock + Trace/Timeline`。
- **展示模式**：适合大屏（高分辨率、可投屏、主持人快捷操作）并提供会后可复现情景链接/摘要；移动端为补充，不是主舞台。
- **视图节奏**：能在30秒建立全貌，能通过1次干预看到链式反应，能在详细检查时还原公式、前提与证据。

## 九、分阶段验证（研发设想，不等于已决定立项）

1. **M0 数据语义样机**：单国家/一产品/分销+ARS链路/明确RRP基数，Margin和库存公式可单元测试。重点P0。
2. **M1 联动画布**：同一状态驱动经营、产品、Margin、ARS、代理、WOS及综合等视图；选中/回退/撤销/重置。重点P1。
3. **M2 假设与时间沙盘**：加入行为响应、多个条件、时滞反馈、情景A/B和追踪回放。重点P2。
4. **M3 视觉完成度**：空间布局稳定后细化动画、材质、排版和高分辨率投屏体验；审美持续迭代并做P3验收。

**不可跳过的检查**：RRP/点位/DP数学闭合；库存物量守恒；WOS分母和统计粒度一致；跨国家货币/税口径不可直接加总；渠道路径与终端店型不得重复统计；代理商考核是观察/评分而非自动因果；行为推演必须保留范围及模型版本；所有演示样本标明合成。
