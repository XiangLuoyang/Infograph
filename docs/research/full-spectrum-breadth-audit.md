# 🗺️ 全领域可视化图表库：覆盖审计与分类体系

> [!abstract] 结论
> **广度验收不通过。** V0.1 已收录 24 个一级分类、630 个去重英文图型名称，但既非 630 种独立表达原理，也无法据此证明覆盖了所有学科。主要缺口在电气电子、地球科学、天文、网络安全、交通工程、化学和运动分析等专业表达体系；另有大量未逐型核验条目。下一轮应先补“学科领域地图”，再做专业图型目录与 HTML 可复现实现。

> [!important] 用户定义的目标范围
> 建立**完整、开放扩展、可证据审计的可视化图表库**，供 AI 按内容需要生成 HTML 图形；不只是传统统计关系图表，也包括工程制图、工业设计、建筑、科学/医学、地理空间、关系拓扑、过程机制、系统建模、业务叙事等。必须把“图型本体 / 专业语义 / 表现方式 / 交互 / 技术实现”分开；不能因为图表数量很多就宣称广度穷尽。

## 二、确定性覆盖缺口：不应只增加孤立图名

以下条目在当前 V0.1 的英文图型名称目录中没有明确独立收录（本轮交叉检索判断）；各专业领域仍需进一步做原始标准和典型图谱审计。

| 待补领域 | 关键遗漏类型 | 建议领域核验入口 |
|:---|:---|:---|
| 电气/电子工程 | 电路原理图、接线图、单线图、梯形图、PCB布线布局 | IEC/IEEE 标准、电气 CAD 与工业控制工具文档 |
| 地质/地球科学 | 地层柱状图、构造剖面、测井曲线、地震解释图 | 地质调查/地学专业出版物与 GIS 规范 |
| 天文学 | H-R 赫罗图、星图、光变曲线 | 天文教材与天文学数据可视化文献 |
| 网络安全 | 攻击树、攻击路径图、MITRE ATT&CK 战术矩阵 | MITRE、NIST 与安全分析平台 |
| 交通工程 | 时空轨迹图、列车运行图、交通流基本图 | 交通工程教材与铁路时刻图规范 |
| 化学/反应工程 | 反应机理图、反应路径、化学工艺 P&ID | IUPAC、化工/工艺与流程标准 |
| 体育运动分析 | 投篮位置分布图、运动轨迹、场地区域控制图 | 运动分析文献与公开体育数据规范 |

> [!caution] 其他可能盲区
> 考古、军事战术、生态学、通信工程、法律、教育、艺术与设计等应列入**待排查队列**，此时不是“已确认所有图形缺失”；需要先建立学科领域地图，再核对专业图型词汇表。

### 为什么此前会漏掉“爆炸图”

上一版图型选型偏重 FT Visual Vocabulary 式统计任务（排名、偏差、趋势、分布、构成等）。**爆炸图（Exploded View）**属于结构解释与部件空间关系表达，既不是传统统计编码，也不只是 3D 材质效果。同类还包括装配图、剖面图、轴测图、透视图、解剖视图等；不能仅把它们看作某种图表的“特殊皮肤”。

## 三、建议采用多轴图形分类，避免把不同概念混成一种图表

| 独立层次 | 问题 | 举例 |
|:---|:---|:---|
| **A 基础形态/编码** | 图由怎样的空间与视觉关系构成？ | 点/线/面、矩阵、树、网络、层级、拓扑、几何体、体数据 |
| **B 专业图型/表达规约** | 它在领域里有什么独立的语义和绘制规则？ | 爆炸图、P&ID、H-R图、地层柱状图、BPMN、桑基图、弦图 |
| **C 表现与交互修饰器** | 以何种视角、渲染材质和交互呈现？ | 2D/2.5D/3D、轴测/透视、X-Ray、玻璃、滚动拆解、钻取 |
| **D 实现与交付** | 如何在浏览器里生成与复现？ | SVG、Canvas、WebGL、Three.js、D3、ECharts、BPMN.js、CAD/GLB输入 |

其中 A–C 为可组合的表达坐标，D 是工程实现维度；不主张所有图形必须严格落到唯一树状分类。一个交互式 3D 爆炸图可以同时具有专业类型“爆炸视图”、投影“透视”、交互“拖动拆装”和 Three.js 实现，但**不能算作四种独立图型**。

## 四、从“收录条目数”转换为“广度验收”

1. **领域发现**：建立不依赖当前 24 分类的学科/行业主题地图，逐域搜集标准、教材、专业图库、软件类型清单；记录检索词和反向检索轨迹。
2. **专业体系覆盖**：每域建立“基础视图—专业命名—行业约定—复合图—典型应用”的图谱；缺少标准来源时标为开放缺口。
3. **同义与变体审计**：建立 canonical ID、中文名、英文名、别名、family、专业属性、基础原理、modifier、参考图、source URL；跨行业复用不重复计数。
4. **验证分级**：L0 候选名称；L1 可信出处直接列名；L2 定义+绘制规约核验；L3 实际可视样例+适用性核验；L4 HTML 代码可运行及交互/数据验收。不能越级声明。
5. **HTML 可生成性**：标注图型适合 SVG / Canvas / D3 / ECharts / WebGL / Three.js / DOM / 外部模型或 CAD 输入；区分“可由原始数据生成”和“必须先拥有几何/空间资产”。
6. **反向遗漏审计**：每次从未用于建库的第三方行业目录抽样，测量新图型发现率与未匹配率；持续扩展时允许新增一级学科，不因当前 taxonomy 封闭候选。
7. **版本一致性**：JSON、README、Excel、HTML 与所有统计/来源标注自动生成自同一数据源并校验，防止 619 与 630 的漂移。

### 达标定义与当前判定

| 维度 | 本轮判定 | 下一阶段门槛 |
|:---|:---|:---|
| 主流统计图表 | 覆盖较充分 | 复核同名变体及来源 |
| 通用信息图解 | 有基础 | 结构图解独立成体系 |
| 科学/工程/专业图形 | 明显不完整 | 专业目录逐域对照 |
| 跨学科广度 | **不通过** | 学科地图 + 缺口关闭记录 |
| 图型本体去重 | 未完成 | 类型/修饰器分离 |
| 逐型来源核验 | **185/630 仅直接列名** | 扩展到定义与示例证据 |
| HTML 组件实测 | 未全量 | 按优先级逐型可复现 QA |

> [!important] 实施顺序
> **先领域地图 → 再全面检索命名图型 → 再去重与语义建模 → 再逐型示例与来源 → 最后 HTML 组件和 Agent Skill。** 不以制造一份很长的名单替代广度覆盖，也不因 630 项而直接宣布可封装通用 Skill。
