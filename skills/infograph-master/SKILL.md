# Infograph Master V1.1
Use the full repository; paths below are relative to this skill unless stated. Do not copy this file alone. Read references/context-guide.md first. Use its compact index to choose initial references; consult references/modes.md only for deeper domain routes. Always load references/acceptance.md and references/design-principles.md; budget cannot waive blocking requirements. Default to Standard for dashboards, Express for a single simple chart. Combine modes when needed; Runtime is optional, never a creativity constraint.

## Execution
**Complex existing dashboards:** if multiple pages/routes/tabs or substantial repeated slices, load `references/system-level-refactoring.md` before the single-artifact route. Enumerate all pages/slices, recover original Design DNA, choose a shared contract, plan every slice and maintain a checkpoint ledger. Do not stop after a few easy edits or import a conflicting local visual style. Assess all, change only justified scope, and review the integrated output across pages.
0. **Existing artifact revision:** when given a dashboard/report/HTML or partial design to optimize, load `references/reconstruction-entry.md` FIRST, before visual critique or edits. Recover business intent from actual evidence, diagnose L5–L1, compare refine/restructure/reinvent, and preserve semantic assets. Use its short path on every host and staged CLI if supported; follow the detailed P0 contract; do not default to cosmetic polish. Explicit narrow scope and critique-only requests override change scope.
1. Identify audience, task, decision, delivery, time budget and data permissions. Ask only for blocking inputs.
2. Reconcile source, units, grain, period, denominators and missingness. Separate facts, inference, assumptions and unknowns.
3. For authored reports establish thesis, evidence and cognitive progression; for monitoring/exploration prioritize user tasks. Do not force a story.
3a. **Visual opportunity discovery (default for substantial work):** load `references/visual-opportunity-discovery.md` before choosing forms, regardless of keyword match. Inventory all slices; review mechanism, dense-table/prose conversion, distinct candidate forms and cross-page visual language. Use the separate authored audit in `engine/visual-opportunity.mjs` or its manual equivalent. Explicitly record justified repetition and retained lookup tables; do not force variety or images.
3b. **Quality-depth production (mandatory applicability review for substantial work):** read `references/quality-depth.md` before form selection. Address narrative director, semantic choreography, art direction, motion completeness, global spatial composition and depth review; apply only task-justified features, and preserve accepted layers. Use `engine/quality-depth.mjs` or the manual equivalent for revision-bound design/review evidence. Coverage does not imply depth; missing rendered evidence blocks declared depth completion. Do not confuse structural audit with aesthetic or user acceptance.
3c. **Interactive narrative route:** when QD01 applies and staged explanation is justified, load `references/narrative-director.md` after the narrative-design storyboard. Use `engine/narrative-director.mjs` or equivalent authored state logic for stable act IDs, semantic cues, separate inspection, playback interruption, reduced motion and shared-context handoff. The host must bind actual data and rendering; static essential evidence remains available. Do not force director mode on monitoring/lookup.
3d. **Semantic choreography route:** when QD02 identifies meaningful visual state changes, read `references/interaction-choreography.md` and use `engine/interaction-choreography.mjs` or equivalent authored transition logic. Declare stable object channels, complete states, evidence, directed transitions, timing dependencies, interruption and static alternatives. Keep transient animation separate from facts; use cuts for unsupported paths or reduced motion. The renderer remains responsible for physical fidelity, accessible controls and actual frame review.
3e. **Concept art production route:** when QD03 identifies a justified rich scene, read `references/concept-art-pipeline.md` before final visual implementation. Compare distinct art directions and plain evidence; inspect the concept, author independent asset/layer work orders, preserve live semantic labels, and plan clean plates/masks for moving parts. Use `engine/concept-art-pipeline.mjs` or the manual equivalent; reuse reference reconstruction or explicit custom hybrid rendering, and review actual concept-to-output fidelity. Declared asset readiness is not verified imagery or aesthetic approval.
3f. **Physical motion completeness route:** when QD04 applies, load `references/motion-completeness.md` before final implementation. Inventory actual concept layers by physical class, assess candidate behaviors and justify static objects, bind finite business-driven motion to P2 and assets to P3, and gate qualitative loops by scene state, pause and reduced motion. Use `engine/motion-completeness.mjs` or manual equivalent; review actual moving frames, geometry, material and containment. No automatic physics or image understanding is implied.
3g. **Global spatial composition route:** when QD05 applies, load `references/global-spatial-composition.md` before final layout. Reuse the complete atlas and design DNA; compare fixed, flow and hybrid workspaces, define viewport width/height tiers, page/slice navigation, stable shell, focal regions, reading order and explicit scroll ownership. Use `engine/global-spatial-composition.mjs` or the manual equivalent for scoped grid structure and viewport-by-slice review. Preserve accepted layers, never clip essential evidence, and inspect actual navigation, overflow, legibility and task reach. No universal single-screen mandate.
4. Choose representation by information relationship and domain. For substantial work compare two genuinely different art directions, then specify color, type, layout, material, chart, interaction and motion.
5. Apply DP01-DP05 from references/design-principles.md: select fit-for-purpose rendering, unify visual language, compose for target devices, design task-led interaction, and protect accepted baselines. Use a reasoned nonapplicability disposition rather than adding unnecessary visual effects.
6. Build the requested artifact with shared data/state, meaningful controls, visible essential evidence, responsive reading order and accessible alternatives. Do not stop at a proposal unless requested.
7. For substantial work re-run visual opportunity review on the actual integrated output; inspect repeated families across different tasks, remaining dense tables/prose, exact-data access and functional regression. Unresolved opportunities or missing revision-bound review block declared visual-opportunity completeness. Apply references/acceptance.md proportionately. Fix blockers and report actual checks, untested items and limitations.

Truth, privacy, domain accuracy and accessibility override aesthetics. Explicit user constraints override defaults. No unauthorized external installation or upload. Never invent evidence, claim causality from correlation, or claim tested superiority without results. Prefer freeform or specialist rendering for unsupported tasks; never bypass invalid data. Keep deliverables proportional: brief, evidence map, design rationale, artifact and validation log can be compact.

For substantive tasks follow references/execution-gates.md before final rendering and review. Missing or stale required evidence blocks declared eligibility; do not fabricate records.

For substantive artifacts review actual evidence and output using references/critique-protocol.md; prioritize material defects over polish, record unknown checks and stop at the revision budget.

For reference-image or concept-to-code reconstruction, load `references/reference-reconstruction.md` before implementation. Use its authored object manifest, renderer routing and evidence ledger; preserve essential labels and stable identity, disclose unsupported fidelity, and do not confuse planning with rendered output or human aesthetic approval.

For abstract business mechanisms or competing constraints where a physical analogy improves explanation, load `references/dynamic-visual-metaphor.md` before choosing a scene. Compare physical mechanisms, define semantic mappings and state transitions, separate qualitative motion from measured evidence, and preserve the accepted baseline. Use only when it serves the reader's task.

For suitable mechanism opportunities, route to `visual-metaphor-intelligence/SKILL.md` before selecting the physical analogy. VMI V0.5 provides authored multi-perspective exploration, creative concept critique, style-conditioned scene compilation and an offline workbench; require open-domain exploration when candidates are weak, compare alternatives and preserve evidence boundaries. Rich rendering handoffs are planning only; use the actual reference renderers and inspect outputs. Do not equate graph match with creative or visual approval. Existing dynamic-visual-metaphor and design-DNA requirements still apply.
