## Execution
For substantial work compare at least two materially distinct art directions and a neutral baseline before styling. Use references/art-direction-production.md and `art-direction-propose` / `art-direction-preview` to compare executable token contracts. Where the bounded families fit, include the selected artDirection brief and rationale in production-plan, reuse its compiled CSS and chart tokens across pages and scenes. For custom or preserved baseline directions explicitly explain why and record equivalent evidence; do not force a preset. Actual screenshot review is still required.
**Execution architecture — candidate workflow (substantial create/redesign/critique):**
1. From the repository/package root execute `node scripts/infograph.mjs preflight`, then `node scripts/infograph.mjs start-workflow <redesign|create|critique> <source> <new-run-dir>`. Read repo:docs/EXECUTION-ARCHITECTURE.md for exact contracts. Keep private run files outside the repository.
2. Execute `status <run-dir>` through the same CLI; use `task <run-dir> <stage>` to obtain the current assignment, references and blank scaffold. Author real evidence; execute `run <run-dir> <stage> <input.json>`. Inspect actual output. Repeat until pre-build eligibility (or critique-ready for critique-only). For reconstruction use actual source observations; do not copy benchmark answers. Use `retry <old-run> <stage> <new-run>` for repair.
3. When a mechanism is selected, execute VMI discovery and packet stages, inspect candidate comparisons and resolve open discovery or explicitly revise the representation choice. Preserve the plain alternative. When specialist-plan is requested run applicable compilers, not a manual imitation. Compiler evidence is not rendered quality.
4. Implement the actual HTML. Run `bind-artifact <run-dir> <output.html> <browser-plan.json>`, `browser-review --trusted <run-dir>` (trusted local HTML only), and `artifact-status <run-dir>`. For material numeric/count/missing-value claims, include read-only `semanticProbes` in the browser plan using references/business-semantic-qa.md, with independent expected values and explicit units. Exercise meaningful boundary and interaction states; where probes are unsuitable, document why and use manual evidence. Inspect every actual capture; run `semantic-task`, `semantic-submit`, `semantic-status` using references/business-semantic-qa.md; known semantic failures block both handoff modes and missing semantic checks block reviewed candidates. Use `critique-task`, `critique-submit`, `critique-status`. Repair via stage retry or `retry-artifact`; no fabricated passes.
5. Before handoff run `delivery-check`, `prepare-handoff` and `verify-handoff`. Only hand off the exact reviewed candidate bytes and disclose limitations. A reviewed candidate requires a complete critique with declared independent-human or independent-model reviewer disposition; identity is not authenticated. An explicitly agreed, labeled unverified draft is allowed for a verified browser-unavailable blocker, or after observed browser pass with missing/incomplete critique and no recorded findings, including complete author self-review. Known findings, browser failure, pending browser execution and stale/tampered evidence remain blocked. If the producing agent cannot inspect images or lacks an independent reviewer, use references/independent-review-handoff.md. An operator-authorized separate local adapter may execute `reviewer-run --trusted-adapter <run-dir> <operator-config.json>` before critique submission. Never invent an adapter/config, authorize external disclosure yourself, or fabricate observations. No shell/repository access means disclosed manual assistance, not equivalent execution. The following design routes still guide creative work; where a canonical CLI stage applies, a manual equivalent is not an alternative to its execution. Host sending enforcement and independent design acceptance remain unverified.
