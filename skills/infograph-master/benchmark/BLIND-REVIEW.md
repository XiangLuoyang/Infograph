# C09-E4 Blind review
Build a new output directory with `node blind-review.mjs benchmark-local benchmark-review blind-output`. Keep PRIVATE-key.json with experiment coordinator only; share review/ and studio HTML, never raw prompts or run IDs. Inspect screenshots for identity leakage. Random opaque IDs and randomized ordering do not guarantee blinding.
Studio records six 0–5 ratings or null and notes, exports JSON. Anchors: 0 absent/incorrect, 1 major defects, 2 partial, 3 adequate, 4 strong, 5 exceptional with evidence. Screenshot-only review cannot establish runtime, interaction or factual correctness; leave unobservable dimensions null. See VISUAL-REVIEW.md for visual critique.
Coordinator uses normalizeReview in normalize-review.mjs with review, private key, records, applicability, adjudications and rubric. Explicit hard-fail adjudication is required; interaction and engineering scores come from verified evidence rather than screenshot guesses. Missing applicable ratings remain not-run. Use analyzeReviewed in review-analysis.mjs with schedule, records, settingsByRun, reviews, key, applicability, adjudications and rubric for paired analysis. Duplicate reviewer/run and mixed settings within a model slot are rejected. These are module APIs, not standalone CLI commands.
Independent reader test: show one artifact, record unprompted thesis, evidence, decision and lookup answers plus elapsed time before showing comparison or answer key. Reader-test UI and independent reviewer calibration remain pending. Native synthetic aggregation tests passed; no actual model artifacts or human ratings are evidenced.
