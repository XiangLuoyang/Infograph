# Blind reconstruction pilot (prepared, not executed)
Goal: test whether the reverse-design workflow improves recovery of business intent and reader task value versus generic cosmetic optimization, without sacrificing semantics. Three synthetic fixtures include one negative control. They are NOT real business evidence and do not prove user-specific utility.

## Setup
Use same exact model, reasoning setting, time/token budget, tool availability, and fresh isolated context. Compare A generic no-skill optimize, B pinned pre-reverse-design skill (commit 1a8840812ba2464b8944b4de5aa7d0723bdfafe5), C current pinned skill with reverse-design workflow. If unable to use identical tools or immutable verified bundles, report differences; do not claim a controlled result. No actual model call is included. One repetition per case/arm gives nine runs, exploratory only.

Coordinator alone reads rubric files and creates packets using prepare.mjs. Only individual input.html and identical prompt go to each model plus permitted pinned skill bundle; never mount the benchmark repository, answer files, previous outputs, history or full coordinator folder. Public rubrics are not confidential: block repo/web access during run, use freshly authored unseen private cases for stronger evaluation, record any leakage. No user business materials in the public repository. The generator receives no original request, reference output or expected answer. Models must output actual revised artifact, brief recovered intent and limitations. Failed runs stay in denominator. Do not guide model toward a specific representation.

## Review
Blind reviewer receives randomized output IDs, original artifact, recovered brief, output and task rubric, not arm/model/commit identifiers. Review actual rendered states and verify metric/function parity first. Hard fail for material wrong/lost data, essential broken behavior, unsupported causal/quantitative assertions or disclosure. Score each 0–4 with cited evidence: intent recovery, semantic preservation, task accuracy, task efficiency, substantive design change where justified, visual coherence, and appropriateness of restraint. 0 absent/wrong, 1 major gap, 2 partial, 3 adequate, 4 strong. Record not-run separately; do not convert missing test to zero. Measure reader lookup/retell answers and elapsed time before showing comparative artifacts. A pretty screenshot cannot establish parity. Negative control must not reward structural changes for their own sake; evaluate preservation and lookup. Report paired case differences, hard failures, time/token costs, limitations and actual reader feedback. No promotion from synthetic smoke alone.

## Status
Fixture preparation and manual protocol only. No blind model runs, independent reviews, or superiority evidence. Actual work dashboards should remain private and be evaluated with the same matched-input protocol.
