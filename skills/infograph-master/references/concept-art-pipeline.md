# Concept Art Pipeline P3 — concept-to-asset production V0.1

Use for QD03 rich visual scenes, not ordinary charts. Start with the evidence-grounded decision and semantic objects, VMI candidate comparison where applicable, and design DNA. A concept image is not the deliverable and a generated image is not automatically good design.

## Production sequence
1. Compare two materially distinct art directions and a plain representation. Specify silhouette, view/camera, composition, palette, materials, lighting and tradeoffs. Select by business semantics, visual expressiveness, feasibility and evidence risk. Reuse accepted visual language. Do not use an industrial metaphor merely because REAL-004 did.
2. Produce an actual concept study if the task authorizes the medium and a suitable tool exists; otherwise use an authored sketch or disclose the limitation. Keep essential business text and values outside the picture. Record source rights, image dimensions, actual SHA-256, reference and inspection evidence linked to that exact image. A failed or not-run inspection prevents declared production readiness. A fixture hash is not actual image evidence.
3. Decompose the source manually with image understanding or an external authorized asset tool. Inventory semantic object IDs, normalized regions, unique compositing depth, role, material/light, occlusion and static fallback. Plan actual assets: clean plate, isolated part, mask, texture, overlay, static fallback or geometry. A clean plate removes the original moving part; it is not simply the original image with another copy superimposed. For a wheel preserve thickness and perspective, isolate the rotating component and correct pivot; for fluid use an interior mask, texture motion and preserved glass/reflection layers. These are case-specific examples. Preserve context and legibility in mobile composition.
4. Use compileConceptArt(spec) to validate the authored plan. buildConceptProductionPacket(plan) exposes the selected visual direction, region/label safe-zone manifest and asset work orders. The caller still generates or extracts real assets and verifies their hashes and rights. Ready flags are declarations; actual asset bytes, segmentation quality, plate continuity, pivot precision and visual fidelity require inspection.
5. For supported reference layers, pass referenceManifest to compileReference and use existing reference-reconstruction.md and reference-renderer.mjs. Bind actual embedded raster bytes using the existing validateRaster validator. The manifest is a renderer candidate, not rendered output; masks/clean plates and correct isolated-part alignment must be prepared by the author. The existing reference renderer does not implement arbitrary texture deformation or masked-fluid composites. If custom-hybrid layers exist, referenceManifest is null; use an explicitly authored custom renderer with static fallback, not a silent lower-quality generic approximation. Keep P1/P2 stable IDs and authoritative data binding via an explicit mapping where multiple layers represent one semantic object.
6. Review the rendered scene vs the concept and accepted baseline: semantic identity, silhouette, perspective, material, lighting, occlusion, legibility; dynamic layers additionally need motion and occlusion records. reviewConceptArt(plan,{outputSha,records}) checks declared evidence tied to concept/output hashes. Use actual artifact SHA and actual review references; do not invent references. This is not a pixel comparison or a substitute for human aesthetic review. Actual animation frames, responsive behavior and reduced motion still need QD02/QD04/QD05 review.

## Input/output
Use engine/concept-art-pipeline.example.json as a synthetic schema illustration. Its hashes, inspection, and asset statuses are test declarations only, not real assets. Layers declare stable id, role, backend, semanticIds, bounds [x,y,w,h] in unit coordinates, depth, essential, dynamic, reason, material, lighting, occlusion, staticAlternative. Dynamic layers also declare motionIntent, pivotOrDomain, motionMapping (qualitative/calibrated; calibrated requires calibrationRef). Dynamic raster and custom hybrid require cleanPlateId, maskId and bakedOriginal:false; essential custom hybrid requires fallbackAssetId. HTML label content is bound separately by the host. Geometry/raster assets carry production description, sourceRef, parentSha; ready assets additionally need a sha256, ref and permission. Local-only source cannot confer publication clearance. This does not authenticate rights.

## Tests and boundaries
Run node test-concept-art-pipeline.mjs from engine. Initial 14 synthetic assertions were executed in development host; subsequent four guards (concept inspection, local-only rights and calibrated mapping) and repository reference compiler integration assertion were added but not yet executed. Actual image generation, asset extraction, rendering, browser QA, independent aesthetics and full repository CI have not been executed for P3. The pipeline integrates existing VMI and reference infrastructure at the contract level; it is not a computer vision model, image generator, 3D material system or automatic art director. REAL-004 is case evidence, not proof of first-pass improvement. Do not publish the original accepted private artifact or concept images.
