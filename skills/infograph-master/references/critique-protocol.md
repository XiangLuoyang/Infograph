# Critique protocol V0.1
Review actual artifact and evidence in six perspectives using critique-rubric.json. Record each check with dimension, check, revision, status, ref; failed checks require severity, issue and concrete repair. Not-applicable needs rationale and cannot waive evidence. Blocker: incorrect or unsupported material claim, unsafe disclosure, misleading geometry, broken essential task. Major: reader cannot follow main argument, meaningful task impaired, substantial visual or responsive defect. Minor: localized polish without material comprehension impact. For authored reports use naked-title and retell tests; distinguish self-review from actual reader tests. For monitoring assess lookup and alert tasks instead of forcing a story. Inspect screenshots only when actually available. Run critiquePlan; repair highest severity first, increment revision and re-review. Default three revisions, stop on repeated check/severity signature or exhausted budget; repeated signature is a conservative proxy, not proof of no improvement. Never claim independent verification from self-reported records. Unknown checks remain incomplete. No automatic repair or release.

Apply DP01-DP05 using the expanded rubric: renderer-fitness, material-coherence, responsive-composition, contextual-focus-fit, baseline-regression and runtime-legibility. Review actual render, whole and changed layers, target-device tasks and accepted baselines. Mark a nonapplicable feature with specific rationale, not-run when evidence is missing. Unreadable essential text is a blocker even when nominal palette contrast passes. User feedback is separate from self-review and CI; stop a revision without falsely declaring acceptance.
