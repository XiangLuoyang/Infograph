# Execution gates V0.1
For substantive tasks maintain a revision-tagged record for each applicable requirement in references/execution-gates.json. Each record has key, revision, status (pass/fail/not-run), ref (actual artifact location or inspectable evidence). Before final artifact generation inspect pre-build gates with engine/execution-gates.mjs auditExecution; missing/stale/failed records block declared eligibility. Report/decision needs thesis, evidence links and storyboard; monitor needs metric priorities, lookup tasks and alert rules (explicit no-alert rationale acceptable). Alternative directions required for substantial tasks. Draft prototypes may be used to investigate, not represented as completed artifacts. Review actual references, truth and quality separately; a declared pass is not independent verification. Never invent refs. No automatic enforcement in external model hosts. Release authorization remains false.
