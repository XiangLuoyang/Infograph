# Global Spatial Composition P5 — workspace contract V0.1

Use when QD05 applies to a multi-page, multi-slice dashboard or interactive workspace. For an existing artifact, first follow system-level-refactoring.md and system-batch-execution.md. Reuse its independently discovered atlas and Design DNA; this compiler does not replace semantic inventory, migration planning, or original artifact preservation.

## Design sequence
1. **Macro:** define page purpose, primary navigation, secondary thematic slices, filter scope and return policy. Compare fixed workspace (stable presentation canvas), natural document flow (reading and narrow screens), and hybrid (stable shell with scrolling workspace). Choose by task and device rather than forcing one screen everywhere. Use a single shell contract per viewport tier; differences in page content should not accidentally resize the shell. If a task legitimately requires a different shell, author a separate explicitly scoped workspace contract and document the transition; V0.1 does not allow silent per-page shell overrides.
2. **Meso:** assign each slice a single focal claim or lookup task, essential focal region, evidence, controls, detail, lookup or notes. Compare density and progressive disclosure. Avoid squeezing all content into a fixed frame: split by coherent theme or switch the tier to hybrid/flow. Preserve all essential information and exact lookup access. A slice is a semantic unit, not an arbitrary screenful.
3. **Micro:** author region rules for labels, chart marks, controls, material and accessibility; inherit the existing design DNA. Do not restyle an accepted illustration merely to fit a new shell. Preserve reading order across visual arrangement, DOM and keyboard order.
4. Define ordered viewport tiers using both minimum width and minimum height, a mandatory final flow fallback, gap/padding and stable header/nav/filter slot heights for fixed/hybrid. Breakpoints are task-authored, not universal. Declare at least one actual review viewport per tier; add short desktop, landscape phone, zoom and boundary states when relevant.
5. Assign exactly one vertical scroll policy per slice/tier: document for flow, workspace for hybrid, none or one justified lookup region for fixed. Horizontal overflow is allowed only in explicitly registered lookup regions. V0.1 deliberately restricts nested vertical scrollers; other legitimate patterns need a separately authored design and review. Never hide overflow to manufacture a pass.

## Compiler and CSS
Input: existing system atlas with complete-declared coverage, independent inventory, pages/slices and evidence refs. The second argument is the spatial spec; see engine/global-spatial-composition.example.json. Specify revision, atlasRef, designDNARef, alternatives, ordered tiers, viewports, per-page purpose/return/filter/slice order and per-slice regions, reading order and tier variants. Grid variants use positive column weights, rectangular named areas and rowSizes (auto or positive weight). Fixed all-auto rows trigger review, not a claim they can never fit.

```js
import {compileSpatialComposition,selectSpatialTier,spatialCSS,auditSpatialReview} from './global-spatial-composition.mjs';
const plan = compileSpatialComposition(atlas, spec);
const css = spatialCSS(plan);
const tier = selectSpatialTier(plan, viewportWidth, viewportHeight);
```

Host markup: top-level data-ig-workspace with data-ig-tier set to the selected tier. Four direct children in order with data-ig-shell values header, nav, filters and work. Keep empty shell slots in place if required for stability. The work element has one active direct child marked data-ig-slice with its stable ID. Other mounted slices must be hidden. Regions are direct children marked data-ig-region in declared semantic reading order. Host owns actual DOM, focus, navigation, global model and filtering, CSS injection, responsive tier change and hidden/active state. Set document margins and outer embedding constraints deliberately; 100dvh assumes a full-viewport workspace. If embedded, use an adapted contract and measure the real host region. Keep scrollable lookup regions keyboard-accessible and labeled. Horizontal-only scrolling can create overflow coupling in CSS; verify actual vertical reach and clipping. The CSS is structural, not a complete aesthetic system. It does not render charts, choose a thesis or automatically split long content. No arbitrary CSS strings are accepted by the compiler.

## Review
Compiler emits viewport x slice reviewMatrix. Capture each actual rendered combination using existing authorized isolated capture tooling or manual observation. Preserve navigation/return behavior and data state during actual transitions. Provide revision/outputSha, measured viewport, tier, verticalOwner/verticalRegion, documentOverflowX/Y, workspaceOverflowY, shellBox and workBox ([x,y,w,h] in viewport CSS px), per-region box/overflowX/overflowY/reachable/clipped/legible and task results navigation, keyboard, touch, returnContext, dataParity, visualCoherence. Each record requires an actual evidence ref. Measure dimensions at comparable scroll positions; review full regions and actual scroll reach, not only screenshots. Fixed/hybrid expected shell covers header/nav/filter rows; work occupies remaining viewport. Flow has no fixed geometry comparison. Default tolerance is 2 CSS pixels, bounded to 4. Do not treat nominal tolerance as permission to hide content. All required checks and plan issues must be resolved before declaring completion. If the host cannot measure an item, mark it unverified.

Audit checks declared observations, not their authenticity. It can flag shell drift, unintended document or workspace overflow, region overflow, inaccessible/clipped content, missing/stale observations and unverified navigation tasks. It does not inspect real DOM, guarantee contrast, prove accessibility, or judge visual composition. Actual screenshots, transitions, and user acceptance remain separate.
