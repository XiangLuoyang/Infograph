# Reference-guided reconstruction — phase 1 (REAL-001)

Load this route when a visual reference or concept image is provided and the requested output must preserve visual intent in a programmable artifact. This route supplements, not replaces, narrative, representation and acceptance. It does not authorize copying private references to public storage.

## 1. Visual decomposition
Inventory each object, role, normalized bounding box [x,y,width,height], depth order, provenance (observed / inferred / authored), source note, ports, fidelity requirement, essential flag and dynamic flag. Use an actual source SHA-256 for images. Distinguish visible observations from inferred 3D geometry and physical parameters. No OCR, object detector or automatic image understanding is supplied by this module; model or human authors the manifest. Use stable IDs across scenes. Record semantic links separately from illustration.

## 2. Hybrid rendering
Run compileReference(manifest, capabilities) in engine/reference-scene.mjs. It emits a deterministic renderer plan: labels HTML, connectors/anchors SVG, flat SVG, simple surface CSS, static photoreal raster, dynamic photoreal/spatial/optical WebGL. Capabilities describe actual available backends, not visual quality. A missing essential backend blocks planning eligibility; optional degradation is a review item. Slots are NOT rendered assets. Raster source assets must be permission-cleared and must not bake essential labels/data into an uneditable background. Use existing engine/hybrid.mjs for native data blocks; this route handles scene objects, not data-series routing. Connect anchors using planLinks; normalized coordinate transforms use image-space axes; rotations use degrees, positive clockwise. For non-square viewports use a uniform world/viewBox or explicit aspect conversion; no physical force simulation.

## 3. Material and lighting
Record material family, authored normalized roughness, metalness, opacity. Use previewReferenceSurfaces in engine/reference-surface.mjs, which calls existing material-renderer and lighting-plan. Its flat approximation expressly reports unsupported metalness, transmission and physical geometry/lighting. Future WebGL adapter must bind actual geometry, PBR materials, environment lighting and camera; do not claim photorealism from CSS gradients or these numeric descriptors. Prefer appropriate fallback, but disclose loss and never downgrade required fidelity silently.

## 4. Fidelity and aesthetics
Use fidelityReview with per-object evidence records: objectId, dimension (semantic/geometry/hierarchy/material/lighting/interaction/accessibility), status, ref, reviewer, note. Required dimensions cannot be waived. Missing evidence is not-run, not a numerical zero. Review against the actual reference at corresponding scene and viewport; distinguish concept fidelity from beauty and semantic correctness. Use existing visual-compare only for compatible captures of the same scene; pixel differences are not an aesthetic score. Require human review of coherence, shape, hierarchy, typography and material quality; record subjective comments rather than inferred satisfaction. No automatic release authorization.

## 5. Deliverables and status
Manifest, routing plan, actual rendered artifact (separate), evidence ledger, screenshot pairs, disclosed degradation and user feedback. Example is a neutral synthetic two-anchor fixture, not a recreation of private REAL-001. Regression protocol remains in benchmark/real-cases/REAL-001. Phase 1 implements validation, routing, anchor updates and review bookkeeping; phase 2 must implement layered renderer and reference-guided visual QA, then compare actual outputs with human review. No aesthetic improvement, real-image decomposition accuracy, or full runtime integration is claimed.

## Phase 2: layered HTML adapter
`node engine/reference-demo.mjs demo.html` from the skill root generates an offline interactive synthetic example. `buildReferenceHTML(manifest, options)` renders authored HTML/SVG/CSS/embedded raster primitives, including no-JS static scene, keyboard, playback, reduced-motion, linked highlights and aspect-aware anchor transforms. `raster` fidelity means authored image content, not photoreal quality. Assets require embedded PNG/JPEG/WebP, declared cleared provenance and verified byte SHA-256; declarations do not prove legal rights. Missing essential fidelity blocks by default; `allowDegraded` only permits a visibly labelled preview. WebGL is not executed. Generic shape/appearance templates, not arbitrary geometry or photoreal rendering. Test `test-reference-renderer.mjs` and `reference-browser-qa.mjs`; browser screenshots/report are CI artifacts. Human review remains separate.
