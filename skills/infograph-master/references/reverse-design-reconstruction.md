# Reverse design & reconstruction (P0)
Trigger: existing HTML/dashboard/report, screenshot or partially built artifact plus optimize, improve, redesign, reconstruct, audit or similar request. Do not treat current layout as the user requirement. Explicit visual-only scope overrides default; critique-only does not authorize edits. Do not run unknown HTML/scripts outside an approved sandbox. Preserve local/private data and never publish originals without permission.

## 1. Decompose actual artifact
For local HTML source, load `artifact-semantic-ir.md` and run the static inspector if supported. Use its observed evidence to seed the inventory and intent graph; never treat static extraction as complete or runtime behavior as tested. Compare the old and new IR as an additional review aid, not a parity certificate.
Inspect source AND rendered views where available, including states, filters, links, drilldown, export, responsive behavior. Source-only or screenshot-only is limited; never infer unseen data, formulas, behavior or hidden states as fact. Inventory six layers: data (source, fields, grain, formula, units, missingness); business (objects, relationships, hypotheses); information (claims/questions, evidence); narrative (reading path and task order); visual (representation, grouping, focal points, style); interaction (controls, state, dependencies, outputs). For each record stable ID, evidence locator (file/line/selector/state/screenshot), status observed/inferred/unknown, essential and locked. Record coverage of all layers, including unknown or concrete nonapplicability. Lock user-approved strengths, not every existing layout choice. Back up baseline.

## 2. Recover intent independently of visual design
Load `runtime-intent-recovery.md`: for authorized trusted standalone HTML, collect named runtime scenarios; use the intent candidate tool as evidence prompts, not a replacement for business reasoning. Compare matched required probes after rebuilding. If runtime unavailable, disclose and use static evidence only.
Derive audience, decision/task, priority questions, functional constraints and evidence boundaries. Classify each requirement explicit (user statement), inferred (artifact evidence + credible alternative + validation route), or unknown. A plausible relationship is not proven causal. Resolve only blocking unknowns; otherwise proceed with reversible labeled assumptions. A report may need a decision story, while monitoring needs lookup and alert tasks; do not impose storytelling on monitoring. Write a design-independent brief containing no inherited chart/layout prescriptions unless required.

## 3. Diagnose from L5 to L1
L5 business purpose/decision; L4 information architecture and narrative/task sequence; L3 representation/mechanism and interaction semantics; L2 spatial composition and hierarchy; L1 typography/material/detail. For each level cite actual artifact evidence, state defect/adequate/unknown/not-applicable, task impact and actionable repair. Trace defects to recovered intent IDs. Generic advice (e.g. improve spacing) without an artifact-specific failure and repair is insufficient. Do not fabricate defects to justify redesign.

## 4. Reset design space and choose change scope
Imagine no existing layout, with the same verified information and functional constraints. Compare three materially different paths: refine (same architecture), restructure (change information organization/representation/interaction), reinvent (change explanatory model or visual mechanism). For each specify concept, reader-task benefit, cost/risk and reason. Compare against current baseline. Select based on evidence, user scope and cost. If high-level defects exist but refine is chosen, explicitly explain disposition; do not claim they were fixed. A qualitative physical analogy is optional, not mandatory; load dynamic-visual-metaphor.md for mechanism explanations. Preserve user-approved features and data semantics.

## 5. Recombine capabilities and build
Trace each selected reference to a recovered intent and design decision: narrative skill for authored decision reports; representation foundations and atlas for data relations; dynamic visual metaphor for mechanism; contextual focus for dense inspection; visual-design, material, motion, composition and specialist routes as needed. Load required references directly even when context budget defers them. Build the requested revision, not only a proposal, unless the user asked for critique. Provide compact before/after rationale and actual artifact. Avoid changes unrelated to the task.

## 6. Preserve semantics and verify task value
Map every original asset to preserve, replace-equivalent, remove or defer. Essential information and controls cannot be removed; replacement needs explicit target and verification. Locked assets require approval evidence for change. Compare source values/formula/units/filters/missingness and behavior under matched inputs; record parity evidence. Define before/after reader tasks linked to intent, baseline, target and method (lookup, retell, decision, state transition). Test at target devices and states. Record pass/fail/not-run and actual refs; no screenshot or browser means visual review unknown, no human test means comprehension improvement unverified. Keep original baseline available. Do not conflate aesthetic preference with task improvement.

## P0 contract
Use engine/reconstruction.example.json as template; fill actual evidence refs (fixture labels are synthetic placeholders). Run node engine/reconstruction-cli.mjs path/to/packet.json before declaring plan eligible and after review. Engine validates declared completeness and traceability, not extraction, semantics, approval authenticity, or actual parity. It does not generate design or inspect HTML; the author/model does those steps. Plan eligibility requires six-layer coverage, intent provenance, L5–L1 diagnosis, three options, selection, mappings, capability routing, reader tasks; review completion requires declared pass with evidence for essential/locked assets, tasks, render and parity. Unknown critical inputs prevent plan eligibility; use a bounded critique if unresolved. No release authorization. This is P0 workflow enforcement for agents using it; independent host adherence and real-case outcome are untested.
