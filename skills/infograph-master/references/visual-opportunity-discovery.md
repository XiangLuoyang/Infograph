# Visual opportunity discovery and whole-artifact orchestration (V0.1)
Status: candidate workflow derived from REAL-003, not a measured general improvement.

## Default trigger and scope
Every substantial dashboard, report, multi-slice revision or custom interactive scene must perform this review, even when the prompt only says “make a dashboard” or “refactor”. Run before choosing charts and again on the final integrated render. For single-chart or explicitly narrow tasks, restrict scope and explain nonapplicability. Do not turn exact lookup into unnecessary artwork. Explicit user constraints, evidence, accessibility and accepted baseline override novelty.

## A. Discover before choosing representation
Enumerate each page/slice using stable IDs and actual source/brief locators; separate relation, reader task, data grain, evidence status and desired decision. Inspect the original text, tables, charts and interaction states on revisions. Consider both conventional and nonconventional expressions when a mechanism, resource constraint, hierarchy, topology, process, spatial relationship, or meaningful state change exists. For each slice record candidates, chosen family, reason, and evidence boundary. For mechanism opportunities load dynamic-visual-metaphor.md; compare two physical analogies and ordinary evidence, state mappings and limits. Load reference-reconstruction.md if a reference image or a deliberately requested concept image is used for HTML reconstruction. Do not require generating an image; only use available and authorized media when the task supports it. Keep dynamic labels and data layers editable. Studio is an optional companion, not permission to add decoration.

## B. Expression audit: tables and prose
A dense table or repeated text block is an opportunity, not an automatic defect. Determine what the reader actually does: rank, compare, detect outliers, find composition, follow change, inspect exact values, read a definition, or act. Convert comparison, relationship and change into the best-fit visual encoding, with detail on demand and precise labels/accessible alternatives. Keep exact lookup, editable grids, audit records and data dictionaries as tables when appropriate. Preserve all fields, drilldown, sort/export and filter context where required. Record why retained visible dense tables are justified, or how replacement retains exact access. Motion only for meaningful transitions, with static/reduced-motion alternatives.

## C. Whole-artifact visual language orchestration
Build an inventory of visible primary/supporting forms and their reader tasks, by page and across pages. Review repeated visual families against the actual information relationships. Repeated bars for like-for-like monitoring can be optimal; repeated bars for unrelated tasks indicate an opportunity to recompose. Compare candidates against semantic accuracy, reading effort, accessibility, interaction utility, coherence and engineering risk. Avoid quotas for variety, novelty scoring, or substituting pie/3D/animation merely to diversify. Use shared color/material/typography and distinct compositions where information warrants it. Make related evidence part of a focal scene rather than another isolated card when that improves the reading path.

## D. Delivery gates (manual or executable)
Before rendering: inventory coverage, candidate comparison, selection rationale, table/prose disposition, mechanism applicability and renderer/layer plan; after rendering: matched actual screenshots/DOM or explicitly mark not-run; verify whole-artifact repetition decisions, data/behavior parity, exact access, focus and mobile/reduced motion. Use engine/visual-opportunity.mjs with an authored inventory and review records; it flags incomplete declared coverage, unaddressed expression opportunities and cross-task repetition for review. It cannot inspect screenshots, infer relations, assess beauty, prove data lineage or authorize a release. Do not present declared completeness as independent evidence.

## Routing examples (not mandates)
Ranking -> common-scale bar/dot; two states -> slope/dumbbell; additive bridge -> waterfall; cross-dimensional match -> matrix/heatmap; part-whole -> stacked bar/treemap/ring when appropriate; flow -> reconciled Sankey or schematic with explicit qualitative mapping; mechanism -> candidate analogy with independent evidence; exact lookup -> table. Repetition across pages may be legitimate for shared comparisons; explain. Use native HTML/SVG for precise data, specialist/3D for genuine domain needs, image assets for illustrative fidelity when appropriate, and layered interaction for inspection. No forced media use.
