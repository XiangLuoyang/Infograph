# VMI compact authoring (opt-in)
The constructor removes repeated mechanical fields, not design judgment. Use the existing packet task and verified exploration; author concepts, P3 reviews, source evidence and selection normally. Keep actual captions, explanations, state highlights, semantic bindings, physical forms, color palette and activation rationales. Never copy a benchmark or invent evidence.

## Workflow
1. Obtain `task <run-dir> vmi-packet`. Keep locked upstream fields or omit them where hydration supports it.
2. For a one-layer essential SVG scene with 2–6 objects and suitable automatic layout, replace `scene` (or leave it null) with `sceneDraft`. Author title, subtitle, staticSummary, objects (id, caption, detail, shapes and/or geometry as permitted by the original compiler), states, initialState and layout. Layout accepts focalObject (actual object ID), intent, ref, optional minSize and focalScale. Do not author desktop/mobile boxes, layer IDs, symbolic waypoints, or physical waypoints. Optional physicalTopology, surfaceRendering and dynamicBindings retain their full original contracts.
3. Optionally replace styles (or leave it an empty array) with styleDrafts: same authored fields except baselineRef, derived from selectedConcept.designDNARef. No automatic palette selection or contrast correction occurs.
4. Optionally replace activation with activationDraft, omitting version only. Author plainComparison, sourceInteraction and all six capability decisions exactly as required by the original gate. Remove the unused activation scaffold; the constructor rejects competing inputs. Do not declare use just because a feature is available. If the automatic composition route is chosen, record the real composition decision and evidence.
5. Run `node scripts/infograph.mjs vmi-author draft.json packet.json`. The output must be a new JSON file; this command never overwrites, compiles, grants eligibility, or issues execution receipts. A packet may mix canonical and draft sections, but never provide competing definitions for one section. Batch form is {scenes:[...]} with each scene's own draft or canonical sections.
6. Run `node scripts/infograph.mjs run <run-dir> vmi-packet packet.json` and inspect the actual results. Preserve draft and constructed input in the private audit trail. Use the existing canonical path for bespoke multi-layer scenes, manual geometry, unsupported shapes, or unsuitable automatic composition. Original compiler and activation gates apply without exception.

## Constructed fields
- Scene conceptId and revision come from the uniquely selected authored concept.
- A single main essential SVG layer and object layer references are generated; no semantic mappings or objects are invented.
- Composition version and auto mode are generated from explicitly authored layout intent; actual geometry is still determined by the existing compiler.
- Style baselineRef and activation version are bound mechanically.
- Conflicting sections, unknown compact fields and inconsistent object IDs/focal object are rejected.
- Constructor output is not proof of semantic fidelity, valid styles, actual fit or aesthetic quality. The canonical compiler and subsequent reviews decide those.

## Deterministic lint and bounded repair
Run `node scripts/infograph.mjs vmi-lint packet.json` before compilation for field-level diagnostics. It uses the same style and box checks as the canonical compiler. Output contains issues, exact paths, expected ranges or enumerations, actual contrast ratios, and eligible repair proposals. Exit 1 means unresolved lint issues. This is a partial check, not a substitute for compilation.
To explicitly apply bounded repairs, run `node scripts/infograph.mjs vmi-lint packet.json repaired.json`. It never overwrites. It writes a new packet only when lint has no unresolved issues. Keep the JSON report with before/after changes in the private run trail; on blocked output, reported changes were attempted in memory only.
- Variant style: only an isolated line/surface contrast failure is eligible. Search toward black/white, max 48 per RGB channel, nearest candidate among those found, actual ratio >=3. Inherit mode, text, accent, warning and other roles are never auto-modified. Re-evaluate actual rendered composition.
- Manual geometry: only explicitly qualitative scenes without symbolic waypoints, physical topology or dynamic bindings; at most 0.1px origin correction, unchanged dimensions, no increased overlap (including label reserve). Large errors require authored decisions or the existing auto layout route.
- Enum/range errors are diagnosed, never guessed. No semantic, source, capability or review fields are fabricated. Automatic layout candidate feasibility is checked by the compiler, not lint. Keep the original canonical route and full verification.

## Scoped retries of compiled packet failures
When a production VMI packet stage has a verifiable executed receipt but is not ready, run `node scripts/infograph.mjs vmi-retry-task <run-dir>`. It reports each scene's actual preview/issue/discovery status, which inputs can be preserved, which need a packet repair, and the count of equivalent failure signatures in the most recent eight scoped attempts. Repeated failures are advisory: change the repair strategy rather than blindly resubmitting. No readiness threshold is relaxed.
Create a patch using the returned shape, e.g. `{"scenes":[{"sliceId":"actual-slice-id","changes":{"scene":{...}}}]}`. Each supplied field is a full replacement of that field, not a nested merge. Allowed fields: targetId, concepts, reviews, selectedConceptId, scene, styles, activation. Omit untouched scenes and fields. The command rejects edits to ready scenes, upstream discovery fields, duplicate IDs, and no-op patches. If any scene requires open discovery, use the existing upstream retry route instead.
Run `node scripts/infograph.mjs retry-vmi <old-run> <patch.json> <new-run>`. This creates an immutable fork with verified dependencies, constructs retry-input.json and pins its byte hash. Then run `node scripts/infograph.mjs run <new-run> vmi-packet <new-run>/retry-input.json`. Inspect actual output, replay, and continue only if eligible. Good scene authoring is reused, but all scenes are recompiled and verified; this is not a compiled-output cache.
If no executed packet receipt exists (e.g. JSON parsing or hard execution failure), use the existing generic retry and diagnostic path. Generic retry also remains available for deliberately revising the whole packet. Never patch raw receipts or historical run inputs. Changes to source or engine still require a new run. A scoped retry is not a release or degradation authorization.
