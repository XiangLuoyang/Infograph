# Open-world discovery P2
1. For substantial mechanism tasks author two or more genuinely distinct abstractions of the same decision, with essential directed edges, evidence reference and status. Roles, conditions and polarities are optional but when declared must be supported. Preserve a plain evidence alternative. The synthetic fixtures are separate test tasks, not examples of one shared decision.
2. Run explorePerspectives. Review views independently, not a pooled score. Inspect unmapped edges, generalized/unknown qualifiers and search truncation. Directional one-hop rules cannot be inverted or chained. Alias normalization is not contextual disambiguation.
3. If no clean complete mapping or fewer than two eligible source domains, or familiar candidates are inadequate, undertake open discovery: formulate function-based queries without object names; explore at least two different source domains where feasible; verify factual mechanism using credible technical sources. Record query, domain, URL, source claim, conditions, graph and limitations. Do not search with private target data. Unknown source = not evidence-backed. No automatic web calls are implemented.
4. Add verified candidate graphs to local working set and rerun. Log rejected candidates and why. Do not persist to the shared corpus without review. If no appropriate option, choose ordinary visual representation. The code does not author abstractions or independently establish truth.
5. For every generalized or unknown mapping review exact relation, direction, condition, role and evidence; reject misleading causality or numerical implication. V0.1 critiqueMapping only accepts V0.1 result shape; Use P3 creative.mjs auditConcept with actual target and corpus and the existing dynamic visual metaphor gates; author qualifier review for generalized, missing or source-only conditions.
6. Domain diversity is a search heuristic, not proof of originality. No quotas for decorative variety or image use.
