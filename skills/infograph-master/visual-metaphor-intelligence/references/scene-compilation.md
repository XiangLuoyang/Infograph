# P4 — style-conditioned scene IR and renderer
Use only after a candidate passes P3. This is a minimal authored SVG/HTML pipeline, not general art creation or image decomposition. Read ../../references/design-dna-sampling.md, ../../references/reference-reconstruction.md, ../../references/dynamic-visual-metaphor.md and DP01–DP05 relative to this file. For existing dashboards use real matched computed style samples and approved Design DNA; demo styles are synthetic. Do not mistake token contrast for actual composed contrast.

1. Bind design DNA: baselineRef matches concept.designDNARef, sampleRef points to actual samples or clearly synthetic fixture, mode inherit/variant and rationale. Set explicit palette roles, font, material family, radius, depth and motion timing. Solid foreground/background contrast validated; still inspect actual visual layers, gradients and states.
2. Compile scene IR with compileScene: actual target/corpus + P3 concept/review, explicit one-panel scene, stable IDs, layer declarations, desktop/mobile boxes, vector primitives, readable labels, descriptions, state labels, highlight set and initial state. Essential semantic objects and edges stay bound to source/target IDs. Review remains revision-bound. The renderer supports qualitative highlights, not measured geometry. It renders SVG primitives only; unsupported renderer requests block rather than silently fall back.
3. For rich artwork, image concept or 3D request, route to existing reference reconstruction and reference renderers with authored manifest, source rights, per-object layer and fidelity requirements. This is manual routing, not a compiled bridge. Never make an unauthorized image, substitute a schematic for required photorealism, or silently drop an essential layer. Keep numeric evidence independently editable.
4. renderSceneHTML supports controlled style variants with identical semantic IR and geometry, no external dependencies, explicit state controls and separate inspection focus. Static state summary without JS; reduced-motion support. Do not claim arbitrary visual style transfer: only authored solid CSS token profiles and SVG primitive roles implemented. Material family is a declaration, not a physically based shader.
5. Inspect actual integrated screenshot, responsive layout, controls, typography, layer coherence, precise semantic links, motion-off and static alternatives. Whole-dashboard style fit requires matched original/revised samples. Human aesthetic and independent comprehension review remain separate.
Demo: node engine/scene-demo.mjs demo.html. Tests: node tests/scene.test.mjs. Synthetic scene and styles are not a production dashboard or Golden reference. No actual physical simulation, external tool calls, full image/3D compilation, or release approval.
